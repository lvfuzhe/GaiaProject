# 完整规则迁移路线

目标是在不修改 PUCT、自博弈和训练器的前提下，用完整《盖亚计划》状态替换
`MiniGaiaState`。规则实现必须先通过确定性重放和属性测试，再进入大规模自博弈。

## 1. 状态模型

将完整状态拆分为以下不可变组件：

- 公共地图：星球、建筑、联盟、卫星和盖亚塑形者。
- 玩家板：资源、能量碗、建筑库存、种族能力和可用特殊行动。
- 研究板：六条轨道、科技板块、最高等级和公开行动槽。
- 计分状态：轮次板块、终局板块、助推板块和当前分数。
- 回合控制：收入、盖亚、行动、清理阶段以及过轮次序。

状态哈希必须包含所有会影响合法动作或未来收益的信息，用于搜索树复用和重复状态缓存。

## 2. 动作系统

不要把每次资源转换都展开为独立的搜索层。建议使用结构化动作：

```text
Action {
  kind,
  target,
  payment_plan,
  optional_choice
}
```

动作编码器负责在结构化动作和固定策略索引之间转换。等价支付方案需要规范化；联邦方案
使用最小卫星路径生成器，并通过渐进拓宽逐步加入搜索节点。

## 3. 实施顺序

1. 完整收入、资源上限和建筑板。
2. 能量碗、燃烧能量、被动充能和拒绝充能。
3. 六条研究轨、科技板块和公开行动。
4. 盖亚化、跨维星球和盖亚阶段。
5. 联盟合法性、最小卫星连接与联盟板块。
6. 助推板块、轮次计分和终局计分。
7. 基础种族，再逐个增加特殊种族规则。
8. 随机地图、科技和计分设置。

每一步都应添加规则示例测试、随机合法对局测试和状态序列化往返测试。

## 4. 网络升级

完整状态不再适合单一扁平 MLP。建议使用三个编码分支：

- 六角地图使用图神经网络或带坐标位置编码的 Transformer。
- 玩家板和研究板使用实体 token 编码。
- 全局轮次、计分和行动玩家信息使用全局 token。

融合后的表示连接自回归策略头和多人价值头。价值头可同时预测排名、最终得分和分差，
通过辅助损失改善前期稀疏反馈。

## 5. 性能门槛

开始 GPU 自博弈前，规则引擎应满足：

- 状态转移和合法动作生成完全确定。
- 随机合法对局能够运行至少十万局而无非法状态。
- 支持批量网络推理，多个 CPU actor 共享 GPU inference server。
- 搜索节点避免深复制大对象，优先使用结构共享或可撤销状态。
- 自博弈、训练和竞技场使用独立随机种子并记录配置。

当前同步单局推理适合正确性验证。规模化训练需要增加 actor/inference-server 批处理层，
这是进入多 GPU 阶段前的必需工作。
